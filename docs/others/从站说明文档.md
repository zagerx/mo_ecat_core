# 从站信息说明

> 本文档完全根据当前代码整理，列出 `ecx_config_init()` 扫描后 SOEM 填充到 `ec_slavet` 的从站信息，以及核心主站、人形机器人应用层实际使用了哪些字段。

## 1. `ecx_config_init()` 能得到的从站信息

`ecx_config_init()` 会遍历总线上的每个从站，从 EEPROM、寄存器读取基本信息，并把从站切换到 `PRE_OP` 状态。

下表中“核心主站使用”指 `src/backend/soem.c` 的 `soem_fill_slave_info()` 和 `soem_backend_read_diagnostics()` 是否把该字段填到 `mo_ecat_slave` / `mo_ecat_slave_state`；“机器人应用使用”指 `examples/cli/robot/robot.c` 的匹配逻辑是否依赖该字段。

| SOEM 字段 | 含义 | 核心主站使用 | 人形应用使用 | 备注 |
|---|---|---|---|---|
| `slavecount` | 总线上发现的从站总数 | 是 | 是（间接） | 决定 `diag.slaves` 数组大小 |
| `configadr` | 配置地址（configured station address） | 是 | 是（间接） | 用于计算 `position = configadr - EC_NODEOFFSET` |
| `aliasadr` | EtherCAT alias 地址 | 是 | 是 | 映射到 `mo_ecat_slave.alias` |
| `eep_man` | 厂商 ID（vendor ID） | 是 | 是 | 映射到 `vendor_id` |
| `eep_id` | 产品码（product code） | 是 | 是 | 映射到 `product_code` |
| `eep_rev` | 修订版本号（revision number） | 是 | 否 | 映射到 `revision_number`，仅展示 |
| `name` | 从站名称字符串 | 是 | 否 | 映射到 `name`，仅展示 |
| `hasdc` | 是否支持分布式时钟 DC | 是 | 否 | 映射到 `has_dc`，仅展示 |
| `pdelay` | 传播延迟（ns） | 是 | 否 | 映射到 `propagation_delay_ns`，仅展示 |
| `state` | 当前 AL 状态 | 是 | 否 | `config_init` 结束时会切到 `PRE_OP`；`read_diagnostics()` 再次读取 |
| `ALstatuscode` | AL 状态码 | 是 | 否 | 非零时表示从站有错误 |
| `mbx_wo / mbx_l / mbx_ro / mbx_rl` | 邮箱写/读地址和长度 | 是 | 否 | 映射到 `mailbox.write/read_address/size` |
| `mbx_proto` | 邮箱协议位图 | 是 | 否 | 映射到 `mailbox.protocol`，并派生 `has_coe/foe/eoe/soe` |
| `SM[] / SMtype[]` | Sync Manager 配置 | 是 | 否 | 映射到 `sm[]` 数组，含地址/长度/标志/类型 |
| `FMMU0func ~ FMMU3func` | FMMU 功能分配 | 是 | 否 | 映射到 `fmmu[]` 数组，0xff 表示未分配 |
| `eep_ser` | 序列号 | 否 | 否 | 当前未使用 |
| `eep_8byte` | EEPROM 是否支持 8 字节读取 | 否 | 否 | 当前未使用 |
| `CoEdetails / FoEdetails / EoEdetails / SoEdetails` | 邮箱协议能力细节 | 否 | 否 | 当前未使用 |
| `blockLRW` | 是否阻塞 LRW | 否 | 否 | 当前未使用 |
| `Ebuscurrent` | E-bus 电流 | 否 | 否 | 当前未使用 |
| `ptype` | 物理端口类型 | 否 | 否 | 当前未使用 |
| `topology` | 端口连接拓扑 | 否 | 否 | 当前未使用 |
| `activeports` | 活动端口位图 | 否 | 否 | 当前未使用 |
| `parent` | 父节点索引 | 否 | 否 | 当前未使用 |

## 2. 核心主站实际使用的字段

核心层把 SOEM 从站信息转换为 `struct mo_ecat_slave`：

```c
slave->position = soem_slave->configadr - EC_NODEOFFSET;
slave->alias    = soem_slave->aliasadr;
slave->vendor_id    = soem_slave->eep_man;
slave->product_code = soem_slave->eep_id;
slave->revision_number = soem_slave->eep_rev;
slave->has_dc = soem_slave->hasdc ? 1 : 0;
slave->propagation_delay_ns = soem_slave->pdelay;
strncpy(slave->name, soem_slave->name, ...);
slave->state.al_state = soem_to_al_state(soem_slave->state);

/* 邮箱 */
slave->mailbox.protocol = soem_slave->mbx_proto;
slave->mailbox.write_address = soem_slave->mbx_wo;
slave->mailbox.write_size = soem_slave->mbx_l;
slave->mailbox.read_address = soem_slave->mbx_ro;
slave->mailbox.read_size = soem_slave->mbx_rl;
slave->has_coe = (soem_slave->mbx_proto & ECT_MBXPROT_COE) ? 1 : 0;
slave->has_foe = (soem_slave->mbx_proto & ECT_MBXPROT_FOE) ? 1 : 0;
slave->has_eoe = (soem_slave->mbx_proto & ECT_MBXPROT_EOE) ? 1 : 0;
slave->has_soe = (soem_slave->mbx_proto & ECT_MBXPROT_SOE) ? 1 : 0;

/* Sync Manager */
for (int i = 0; i < EC_MAXSM; ++i) {
    slave->sm[i].start_address = soem_slave->SM[i].StartAddr;
    slave->sm[i].length = soem_slave->SM[i].SMlength;
    slave->sm[i].flags = soem_slave->SM[i].SMflags;
    slave->sm[i].type = soem_slave->SMtype[i];
}

/* FMMU */
slave->fmmu[0].function = soem_slave->FMMU0func;
slave->fmmu[1].function = soem_slave->FMMU1func;
slave->fmmu[2].function = soem_slave->FMMU2func;
slave->fmmu[3].function = soem_slave->FMMU3func;
```

诊断更新：

```c
states[i].al_state = soem_to_al_state(soem_slave->state);
states[i].error = (soem_slave->ALstatuscode != 0) ? 1 : 0;
states[i].al_status_code = soem_slave->ALstatuscode;
states[i].online = 1;
states[i].operational = (states[i].al_state == MO_ECAT_AL_STATE_OP) ? 1 : 0;
```

## 3. 人形机器人应用实际使用的字段

人形拓扑匹配只依赖 4 个稳定身份字段，避免把配置绑定到运行期数组下标：

```c
slave->alias == match->alias &&
slave->position == match->position &&
slave->vendor_id == match->vendor_id &&
slave->product_code == match->product_code
```

## 4. SM type 与 flags 含义

### SM type

| type 值 | 含义 |
|---|---|
| 0 | 未使用（unused） |
| 1 | 邮箱写（MbxWr）：主站写给从站的邮箱 |
| 2 | 邮箱读（MbxRd）：从站回给主站的邮箱 |
| 3 | 过程数据输出（Outputs）：主站 → 从站 |
| 4 | 过程数据输入（Inputs）：从站 → 主站 |

### SM flags

`flags` 是 Sync Manager 配置寄存器的 32 位组合值：

```c
SMflags = ControlRegister + (ActivateRegister << 16)
```

它编码了：

- **方向**：主站读还是写这片内存
- **缓冲区模式**：单缓冲 / 双缓冲 / 三缓冲
- **是否激活**：SM 是否启用
- **看门狗触发**：是否触发 watchdog

典型示例：

```text
SM[0]: flags=0x00010026  → 邮箱写，已激活
SM[1]: flags=0x00010022  → 邮箱读，已激活
SM[2]: flags=0x00010064  → PDO 输出，已激活
SM[3]: flags=0x00010020  → PDO 输入，已激活
```

`0x0001xxxx` 中的 `0x0001` 表示 **Activate=1（SM 已启用）**，低 16 位是具体的控制属性。

## 5. FMMU 功能码含义

| FMMU 功能码 | 含义 |
|---|---|
| 0x00 | 未使用（unused） |
| 0x01 | 输出区（outputs）：主站写，从站读 |
| 0x02 | 输入区（inputs）：从站写，主站读 |
| 0x03 | SM 状态区（SM status）：通常用于状态/诊断映射 |

典型示例：

```text
FMMU: [0]=0x01 [1]=0x02 [2]=0x03 [3]=0x00
```

含义：

- `FMMU[0] = 0x01` → 输出过程数据
- `FMMU[1] = 0x02` → 输入过程数据
- `FMMU[2] = 0x03` → SM 状态
- `FMMU[3] = 0x00` → 未使用

## 6. 未使用字段的说明

当前代码只实现了“发现总线”这一阶段，因此大量与 PDO 映射、邮箱协议细节、DC 同步、拓扑分析相关的字段尚未被使用。后续实现 `configure / activate / cycle` 时，以下字段会逐步被使用：

- `SM[] / SMtype[]` —— PDO 映射
- `FMMU0func ~ FMMU3func` —— FMMU 分配
- `hasdc / pdelay` —— DC 同步配置
- `mbx_* / CoEdetails` —— 邮箱通信、SDO 读写

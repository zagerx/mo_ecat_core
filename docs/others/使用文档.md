# mo_ecat_core 使用文档

## 一、获取代码并初始化子模块

```bash
git submodule update --init --recursive
```

## 二、配置

网口由应用层配置文件 `examples/cli/config/master.yaml` 指定（核心库不预设网口）：

```yaml
version: "1.0"
master:
  interface: "enp0s31f6"   # 改成实际的 EtherCAT 网卡名
```

机器人关节身份配置在 `examples/cli/config/robot_config.c`（`robot.yaml` 为同内容模板）。

## 三、一键构建并运行

`examples/setup.sh` 从 `master.yaml` 读取网口、完成构建，并以该网口启动 CLI：

```bash
./examples/setup.sh
```

只构建不运行：

```bash
./examples/build.sh
```

产物：

- `examples/cli/build/ecat_cli`
- `examples/cli/build/core/libmo_ecat_core.a`

## 四、手动构建与运行

```bash
cd examples/cli
cmake -B build .
cmake --build build -j$(nproc)
sudo ./build/ecat_cli <interface>
```

> 打开原始套接字需要 root 权限。启动后依次执行 `scan`、`configure`、`activate`
> 进入周期运行，命令详见 [指令说明文档.md](指令说明文档.md)。

## 五、在其他项目中使用核心库

以 `add_subdirectory` 引入源码并链接 `mo_ecat_core`（`examples/cli/CMakeLists.txt` 即示例）：

```cmake
add_subdirectory(<path-to-mo_ecat_core> <binary-dir>)
target_link_libraries(your_app PRIVATE mo_ecat_core)
```

创建主站时由应用层注入配置。配置为指针语义：主站不复制内容，
配置对象由应用层持有并保证唯一，且必须比主站存活更久：

```c
static struct mo_ecat_master_config s_config = {
    .interface_name = "enp0s31f6",
};

struct mo_ecat_master *master =
    mo_ecat_master_create(&s_config, cyclic_callback, user_data);
```

# ecat_cli 指令说明文档

> 适用对象：`examples/cli` 构建的 `ecat_cli`。
> 主站状态机为五态：`INIT / IDLE / READY / RUNNING / FAULT`。

## 1. 状态模型

| 状态 | 含义 |
|---|---|
| `INIT` | 主站已创建，尚未进入空闲 |
| `IDLE` | 空闲，可接受 `scan` / `configure` |
| `READY` | 已完成扫描、DC 配置与 PDO 映射，可接受 `activate` |
| `RUNNING` | 周期过程数据运行中 |
| `FAULT` | 故障，只能 `reset` 回 IDLE |

所有控制类命令都是**异步**的：命令只写入主站命令槽，由后台调度线程执行。
打印 `xxx requested.` 仅表示命令已被接受，不代表总线动作已完成；
用 `state` 观察实际状态迁移。

## 2. 命令一览

| 命令 | 前置状态 | 作用 |
|---|---|---|
| `help` / `h` | 任意 | 打印命令帮助 |
| `state` / `status` | 任意 | 打印主站状态与已发现节点数 |
| `scan` | IDLE | 请求扫描总线：打开网口、发现从站、读取 PDO 描述 |
| `configure` | IDLE（已扫描） | 配置 DC 并建立 PDO 映射，完成后进入 READY |
| `activate` | READY | 发送过程数据、全站切 OP，进入 RUNNING |
| `deactivate` | RUNNING | 停止周期运行 |
| `reset` | FAULT / READY | 释放资源，回到 IDLE |
| `diag` | 已扫描 | 打印各节点身份与诊断：位置/别名/vendor/product/revision、AL 状态、状态码、DC 能力 |
| `topology` | 已扫描 | 按 `cli/config/robot_config.c` 的关节身份匹配节点，构建并打印机器人拓扑 |
| `cyclic <idx>` | 已配置 | 打印第 idx 个 PDO 条目：节点、对象字典索引/子索引、方向、位长 |
| `exit` / `quit` | 任意 | 退出程序 |

## 3. 典型流程

```text
> scan          # IDLE 下请求扫描
> state         # 确认 Node count > 0
> diag          # 查看从站身份与 AL 状态
> topology      # 校验关节与节点匹配
> configure     # DC + PDO 映射，成功后进入 READY
> cyclic 0      # 查看 PDO 条目
> activate      # 进入 RUNNING，从站切 OP
> deactivate    # 停止周期运行
> reset         # 释放资源回 IDLE
> exit
```

## 4. 启动方式

```bash
sudo ./ecat_cli <interface>
```

网口由命令行参数指定并在创建主站时绑定；通常不直接敲这条命令，
而是用 `examples/setup.sh`——它从 `cli/config/master.yaml` 读取网口后启动。
打开原始套接字需要 root 权限。
